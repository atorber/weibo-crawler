# 定期自动与增量爬取

对于长期监测或者追踪特定名人/博主的需求，爬虫支持自动增量拉取最新数据，避免重复抓取历史微博，节省宝贵的网络请求与时间。

---

## 方案一：Web 控制台「持续监听模式」（7×24 小时无人值守，强烈推荐）

默认情况下，点击「启动任务」属于**单次运行（爬完即停）**：爬虫按顺序遍历完 `user_id_list.txt` 中的目标博主后子进程会自动退出，并将每位博主的 `since_date` 自动推进更新为其最新一条微博的发布时间（精确到秒）。

如果你希望持续追踪目标博主是否发布了新微博，只需在 Web 控制台中开启 **「⏰ 持续监听模式（定时增量巡检）」**：

1. **一键开启持续监听**：
   - 在控制台首页 **「总览控制 -> 爬虫进程核心控制台」** 卡片中（或 **「参数配置 -> 基础采集参数」**），直接打开 **「⏰ 持续监听模式」** 开关，并选择巡检间隔（支持每 5 分钟、10 分钟、15 分钟、30 分钟、1 小时、2 小时、6 小时）。
   - 开启时若爬虫处于空闲状态，将自动立即触发首轮巡检。
2. **防重叠智能倒计时**：
   - 调度器严格在**上一轮爬取任务完全结束后**才开始计算下一轮间隔倒计时（界面实时显示 `🟢 持续监听已开启 · 下次巡检倒计时 Xm Ys`），绝不会产生多进程并发冲突。
3. **秒级增量拉取 + Cookie 自动热恢复**：
   - 由于每轮抓取后 `user_id_list.txt` 都已记录每位博主的最新微博时间戳，后续每轮定时巡检只需数秒即可判断是否有新动态，发现新微博立即入库（SQLite / Markdown / Webhook）。
   - 配合 **「🔄 浏览器 Cookie 自动更新与 403 失效热恢复」**，可真正实现 7×24 小时无人值守动态监控。

```json
// config.json 中的持续监听配置项
"schedule_config": {
  "enabled": true,
  "interval_minutes": 30
}
```

## 方案二：独立动态记录文件（高阶批量推荐）

当需要监控成百上千个博主、且每个博主发博频率差异极大时，方案二是最佳实践：

1. 创建 `user_id_list.txt`，并在 `config.json` 中配置 `"user_id_list": "user_id_list.txt"`。
2. 初始文件格式支持附加起始日期或留空：

```text
1669879400 迪丽热巴
1223178222 胡歌 2024-01-01
1729370543 郭碧婷 3 梦想,旅游
```

3. 爬虫每次爬取成功后，会**自动将每个用户的最新抓取时间回写更新到该 txt 文件第三列**。
4. 下次程序再度执行时，自动读取每行博主各自上一次爬取的最新日期作为新的 `since_date`，真正做到各用户增量相互隔离、互不干扰。

## 方案三：动态天数增量与系统 Crontab

将 `config.json` 中的 `since_date` 设为正整数：

```json
{
  "since_date": 7
}
```

表示每次执行仅抓取从**“当前时间倒推 7 天”**内发布的微博。配合系统自带的定时任务工具（Linux Crontab、Windows 计划任务等）每 7 天或每 3 天触发一次脚本即可：

```bash
# 每周日凌晨 2:00 自动执行爬虫 CLI
0 2 * * 0 cd /path/to/weibo-crawler && /usr/bin/python3 weibo.py >> log/cron.log 2>&1
```

## 方案四：追加模式 (Append Mode)

在 `const.py` 文件中，将运行模式切换为 `append`：

```python
'MODE': 'append'
```

以追加模式运行时，程序仅拉取每个博主主页的最新微博，一旦检测到已采集过的数据即刻终止本次迭代，最大程度节省网络流量与请求频次。
